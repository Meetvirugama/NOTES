## Start Here: The Big Picture {#big-picture}

> **Summary:** Forecasting time series is a fundamental sequential modeling task. Before constructing complex recurrent networks, it is essential to establish naive and linear baselines. The workflow progresses from Simple RNNs to stacked Deep RNNs, culminating in Sequence-to-Sequence models designed to predict multiple future steps simultaneously, ensuring the model optimizes predictions at every time step.

### What is Time Series Forecasting?
A time series is a sequence of data points collected in chronological order (e.g., daily temperature readings: Day 1: 22°C, Day 2: 23°C, Day 3: 21°C). Unlike standard machine learning datasets where observations are independent, order is paramount in time series analysis.

The primary objective is mapping the **Past $\rightarrow$ Future**. For example, given the past 50 daily stock prices, the model must predict the subsequent 10 prices.

## 1. Dataset and Evaluation Baselines {#dataset-baselines}

To demonstrate forecasting, we utilize a synthetic univariate time series where each input sequence consists of 50 time steps.

![Time Series Example](../Visuals/06_time_series_example.png)
**Graph 06:** Examples of synthetic time series generated by combining random sine waves with additive noise.

### Why Use Synthetic Data?
Rather than utilizing real-world financial or meteorological datasets, generating artificial data provides distinct advantages in educational and controlled research environments:
- **Scalability**: Infinite data can be generated on demand.
- **Controlled Complexity**: The underlying periodic signals and noise patterns are known mathematically.
- **Evaluation Simplicity**: Models can be evaluated against theoretically perfect deterministic patterns.

While synthetic, the generated data behaves similarly to real-world periodic signals (e.g., replacing temperatures like `22, 24, 26` with synthetic signal values like `0.12, 0.43, 0.65`).

### Understanding the Generated Dataset
The dataset tensor exhibits the shape: `(batch_size, time_steps, features)`. For example, a shape of `(10000, 60, 1)` indicates:
- **10,000** distinct sequences.
- **60** chronological time steps per sequence.
- **1** feature per time step (univariate data).

### Target Sequence Logic: Why Generate 60 Steps?
A common point of confusion is why 60 steps are generated when the model only accepts 50 input steps. This is structured to separate historical context from future targets:
- **50 steps** serve as the Input (Historical Context).
- **10 steps** serve as the Target (Future Prediction).

For a sequence consisting of steps 1 through 60, the input sequence is steps $1 \dots 50$, and the target sequence is steps $51 \dots 60$.

### Why Predict the Future?
The fundamental premise of forecasting is learning the mapping from Past $\rightarrow$ Future, rather than mapping Current $\rightarrow$ Current. Given temperature readings of $20, 22, 24, 25, 26$, the network is trained to predict the continuation $27, 28, 29$.

### Evaluation Metric: Mean Squared Error (MSE)
Forecasting continuous values constitutes a regression problem. Consequently, the primary evaluation metric is **Mean Squared Error (MSE)**. MSE calculates the average squared difference between the predicted values ($\hat{y}$) and the actual ground truth values ($y$). A lower MSE indicates superior predictive accuracy.

### Synthetic Data Generator Code
```python
import numpy as np

def generate_time_series(batch_size, n_steps):
    freq1, freq2, offsets1, offsets2 = np.random.rand(4, batch_size, 1)
    time = np.linspace(0, 1, n_steps)
    # Combine two sine waves with random frequencies and offsets, plus gaussian noise
    series = 0.5 * np.sin((time - offsets1) * (freq1 * 10 + 10))  # wave 1
    series += 0.2 * np.sin((time - offsets2) * (freq2 * 20 + 20)) # + wave 2
    series += 0.1 * (np.random.rand(batch_size, n_steps) - 0.5)   # + noise
    return series[..., np.newaxis].astype(np.float32)

# Generate splits
n_steps = 50
series = generate_time_series(10000, n_steps + 10) # 50 steps input, 10 steps target
X_train, Y_train = series[:7000, :n_steps], series[:7000, -10:, 0]
X_valid, Y_valid = series[7000:9000, :n_steps], series[7000:9000, -10:, 0]
X_test, Y_test = series[9000:, :n_steps], series[9000:, -10:, 0]
```

### Baseline 1: Naive Forecasting
The naive baseline operates on the assumption that the future value at step $t+1$ will be exactly equal to the observed value at step $t$.
```python
# To forecast 1 step ahead: predict value at step 50 as prediction for step 51
Y_pred_naive = X_valid[:, -1] # Shape: [2000, 1]
naive_mse = np.mean(keras.losses.mean_squared_error(Y_valid[:, 0:1], Y_pred_naive))
# OUTPUT: Naive MSE ≈ 0.020
```

### Baseline 2: Linear Regression
A fundamental principle of machine learning is to evaluate performance against simple baselines. A linear model maps the 50 past steps directly to a future prediction. If historical values exhibit a consistent trend (e.g., increasing by $+2$ every step), a linear model will detect this instantly and perform exceedingly well. One should never assume an RNN will automatically outperform a linear baseline on simple trends.

To process sequential data via a dense linear model, the temporal dimension must be flattened. Dense layers require inputs of shape `(batch_size, features)`. The `Flatten` layer converts the temporal input `(7000, 50, 1)` into a flat vector `(7000, 50)`.

```python
from tensorflow import keras

model_linear = keras.models.Sequential([
    keras.layers.Flatten(input_shape=[50, 1]),
    keras.layers.Dense(1)
])
model_linear.compile(loss="mse", optimizer="adam")
model_linear.fit(X_train, Y_train[:, 0:1], epochs=20, validation_data=(X_valid, Y_valid[:, 0:1]))
# OUTPUT: Linear FCN MSE ≈ 0.004
```

## 2. Implementing a Simple RNN in Keras {#simple-rnn}

A basic RNN layer containing a single recurrent neuron unrolled over the 50 time steps.
```python
model_simple_rnn = keras.models.Sequential([
    # 'None' allows sequences of variable length. 1 feature dimension.
    keras.layers.SimpleRNN(1, input_shape=[None, 1])
])
model_simple_rnn.compile(loss="mse", optimizer="adam")
model_simple_rnn.fit(X_train, Y_train[:, 0:1], epochs=20, validation_data=(X_valid, Y_valid[:, 0:1]))
# OUTPUT: Simple RNN MSE ≈ 0.014
```

### Why Did the Simple RNN Underperform?
Comparing the baseline results:
- Naive: `0.020`
- Simple RNN: `0.014`
- Linear Regression: `0.004`

A single recurrent neuron (`SimpleRNN(1)`) acts as an extreme bottleneck. It forces the network to compress all historical context into a single floating-point number at every step. This limited memory capacity, compounded by vanishing gradients and optimization difficulties, results in poorer performance compared to the unconstrained linear model.

### Understanding Recurrent Units and Variable Sequence Lengths
To address the bottleneck, we increase the number of units: `SimpleRNN(20)`. This instantiates 20 recurrent neurons. At every time step, the input is processed to yield 20 internal hidden values, significantly expanding the memory capacity and expressiveness of the network.

Furthermore, defining the input shape as `[None, 1]` enables the network to process variable-length sequences (e.g., 50, 100, or 300 time steps) without architectural modifications. This flexibility arises because RNNs share identical weight matrices ($W_x$ and $W_y$) across all temporal steps.

## 3. Deep RNNs: Stacking Recurrent Layers {#deep-rnns}

To model hierarchical complexity, recurrent layers are stacked to form Deep RNNs.

![Deep RNN Unrolled](../Visuals/07_deep_rnn_unrolled.png)
**Graph 07:** A stacked Deep RNN unrolled through time. Outputs from lower recurrent layers feed into the inputs of higher recurrent layers.

### Why Do Deep RNNs Perform Better?
In a shallow network, a single layer attempts to learn all temporal patterns simultaneously. In a deep network, representations are learned hierarchically:
- **Layer 1** may detect basic trends (e.g., an overarching upward trajectory).
- **Layer 2** may detect cyclical variations (e.g., weekly seasonality).
- **Layer 3** synthesizes these hierarchical features to form a highly robust prediction.

### Stacking Rules and Shape Conversions
For all recurrent layers except the final one, the parameter `return_sequences=True` must be explicitly set. Without this, the layer outputs a 2D tensor representing only the final time step, resulting in a shape incompatibility error when feeding into the subsequent recurrent layer.

**Step-by-Step Tensor Shapes Trace:**
* **Input**: `[Batch Size, 50, 1]`
* **SimpleRNN(20, return_sequences=True)** $\rightarrow$ Output Shape: `[Batch Size, 50, 20]`.
* **SimpleRNN(20, return_sequences=True)** $\rightarrow$ Output Shape: `[Batch Size, 50, 20]`.
* **SimpleRNN(1, return_sequences=False)** $\rightarrow$ Output Shape: `[Batch Size, 1]`.

```python
model_deep_rnn = keras.models.Sequential([
    keras.layers.SimpleRNN(20, return_sequences=True, input_shape=[None, 1]),
    keras.layers.SimpleRNN(20, return_sequences=True),
    keras.layers.SimpleRNN(1) # return_sequences=False
])
# OUTPUT: Deep RNN MSE ≈ 0.003
```

### Improving Performance with a Dense Output Head
An architectural flaw in the preceding model is concluding with `SimpleRNN(1)`. This forces the final recurrent state to collapse into a single dimension before prediction. 

A superior architectural design concludes the recurrent stack with a high-dimensional state (e.g., `SimpleRNN(20)`), followed by a standard `Dense(1)` layer to compute the final regression output. This preserves 20 dimensions of internal memory throughout the entire sequence processing, allowing for a much more expressive final projection.

```python
model_dense_head = keras.models.Sequential([
    keras.layers.SimpleRNN(20, return_sequences=True, input_shape=[None, 1]),
    keras.layers.SimpleRNN(20), # Output shape: [Batch, 20]
    keras.layers.Dense(1) # Linear projection
])
```

## 4. Forecasting Several Steps Ahead {#multi-step-forecasting}

Predicting multiple steps into the future requires distinct architectural strategies.

![Multi-Step Forecasting](../Visuals/08_forecasting_ahead.png)
**Graph 08:** Comparison of error propagation in recursive 1-step-ahead forecasting vs. direct sequence-to-sequence forecasting.

### Approach A: Recursive Forecasting
Predict step $t+1$, append this prediction to the input sequence, and utilize this extended sequence to predict step $t+2$.
* **The Error Drift Problem**: If the prediction for step $t+1$ contains error, that error becomes the input for the next step. Errors accumulate and amplify rapidly, leading to severe predictive drift over time.

### Approach B: Sequence-to-Vector (Seq-to-Vec) Multi-Step Output
Train a model to process the 50 historical steps and output all 10 future values simultaneously at the final computational step.
* **Advantage**: Eliminates recursive error drift.
* **Disadvantage**: Loss is calculated solely at the final time step, providing sparse gradient signals during backpropagation.

```python
model_seq_to_vec = keras.models.Sequential([
    keras.layers.SimpleRNN(20, return_sequences=True, input_shape=[None, 1]),
    keras.layers.SimpleRNN(20), # Output shape: [Batch, 20]
    keras.layers.Dense(10) # 10 outputs representing steps t+1 through t+10
])
# OUTPUT: Seq-to-Vec MSE ≈ 0.008
```

### Approach C: Sequence-to-Sequence (Seq-to-Seq) Multi-Step Output
Train the model to predict the next 10 steps at **every single time step** of the sequence. Instead of predicting only at the conclusion of the sequence, Step 1 predicts steps 2 through 11; Step 2 predicts steps 3 through 12, and so forth.

* **Why it is superior**: The loss function is evaluated across the entire sequence. This structural density provides continuous gradient signals, stabilizing training and accelerating convergence.

This is implemented by wrapping the output `Dense` layer in Keras's `TimeDistributed` layer. The `TimeDistributed` wrapper applies the identical Dense weights to every temporal slice independently, mapping the `[Batch, 50, 20]` recurrent output to a `[Batch, 50, 10]` sequence of predictions.

```python
model_seq_to_seq = keras.models.Sequential([
    keras.layers.SimpleRNN(20, return_sequences=True, input_shape=[None, 1]),
    keras.layers.SimpleRNN(20, return_sequences=True),
    keras.layers.TimeDistributed(keras.layers.Dense(10))
])

# Evaluate MSE strictly on the final relevant sequence step
def last_time_step_mse(Y_true, Y_pred):
    return keras.metrics.mean_squared_error(Y_true[:, -1], Y_pred[:, -1])

model_seq_to_seq.compile(loss="mse", 
                         optimizer=keras.optimizers.Adam(learning_rate=0.01), 
                         metrics=[last_time_step_mse])
```

## 5. Methodology Comparison {#comparison}

| Method | Prediction Scope | Primary Advantage | Primary Disadvantage |
|--------|------------------|-------------------|----------------------|
| **Naive** | Next value = current value | Extremely simple baseline | Poor predictive accuracy |
| **Linear** | One future value | Strong foundational baseline | Incapable of modeling complex temporal dependencies |
| **Simple RNN** | One future value | Learns temporal patterns | Susceptible to vanishing gradients and limited memory |
| **Deep RNN** | One future value | Hierarchical feature extraction | Higher computational requirement |
| **Recursive** | Multiple future values | Relies on a standard single-step model | Severe error accumulation (Error Drift) |
| **Seq-to-Vec** | All future values simultaneously | Eliminates recursive error drift | Sparse gradient flow (loss computed only at sequence end) |
| **Seq-to-Seq** | Future values at every time step | Dense gradient flow, highly stable training | Increased memory overhead during training |

## Common Beginner Mistakes {#mistakes}

**Forgetting `return_sequences=True` in stacked RNN layers**
> **Why it fails:** Submitting a 2D tensor of shape `[batch_size, units]` to an intermediate recurrent layer results in a structural crash: `ValueError: Input 0 is incompatible with layer... expected ndim=3, found ndim=2`.
> **The Fix:** Ensure all intermediate recurrent layers have `return_sequences=True`.

## Interview Q&A {#interview}

**Q1: Why does a Sequence-to-Sequence architecture train more stably than a Sequence-to-Vector architecture for time series forecasting?**
> **A:** In a Sequence-to-Vector model, the loss is calculated exclusively at the final time step. Gradients must backpropagate through the entire temporal chain, leading to unstable or vanishing gradients. In a Sequence-to-Sequence model, the loss is calculated and backpropagated at every time step, providing immediate, dense gradient signals that facilitate faster and more stable convergence.

**Q2: What is the mechanical function of the `TimeDistributed` layer?**
> **A:** The `TimeDistributed` layer applies a specified standard layer (e.g., `Dense`) independently to every temporal slice of a sequence. Mechanically, it reshapes the 3D input `[batch_size, time_steps, features]` into a 2D matrix `[batch_size * time_steps, features]`, executes the dense matrix multiplication, and reshapes the output back to 3D. This enforces strict weight sharing across time steps.
